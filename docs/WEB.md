# 阶段 3：浏览器牌桌

`python3 -m mahjong_sandbox serve` 在 `127.0.0.1:8765` 启动本地 HTTP 服务。
Python 标准库提供服务，原生 HTML/CSS/JavaScript 提供界面；无 npm、外部 CDN、图片下载或网络字体依赖。前端资源作为 Python 包数据发布，可从安装后的包启动。

## 玩法与界面

- 真人固定坐 0 号庄家，另三家为独立、种子可复现的 AI。
- 换三张必须同门；定缺后缺门牌优先打出，不合法的手牌会变灰。
- 点击选牌并确认，双击出牌，或选牌后按 Enter；Escape 清除选牌。
- 碰、暗杠、大明杠、加杠、荣和、自摸、过牌按钮来自服务端合法动作。
- 自动过牌只跳过唯一合法动作为“过”的响应；关闭后每次应牌都由玩家确认。
- 所有胡牌者退出行牌，其余玩家继续。结算展示各家分数、番种、杠分与荒牌支付账本。
- 四家手牌、副露、缺门、分数、胡牌状态及牌河可视化；点击牌河可放大查看全部弃牌。
- 动画可关闭，声音默认关闭。桌面显示动态侧栏；窄屏保留完整牌桌和操作，手牌可横向滚动。

## 引擎边界

`GameSession` 包装同一个 `Engine`，每次接收真人动作后运行三家 AI，直到下一次真人决策或终局。引擎负责规则、裁决和结算，浏览器只负责选牌和展示。动画是动作完成后的公开状态序列；无需另建浏览器麻将引擎。

所有真人动作带 `decision_id`。已过期、重复或非法动作返回 409，引擎状态保持不变；客户端重新取当前牌桌状态。会话锁避免同一桌并发提交交错。

三个策略均只读取该座位的 `Observation`：

| 策略 | 行为 |
| --- | --- |
| `greedy` | 胡牌优先；选择较少花色定缺，参考牌型距离换牌、碰杠和弃牌；同距离优先更多有效进张 |
| `win-first` | 胡牌优先，其余合法动作随机 |
| `random` | 均匀随机合法动作 |

牌效策略是参考基线，没有牌山或对手暗牌输入，也没有训练过的模型。其结构距离包含普通和型、川麻七对及已有副露；不应把它视为优化算子或完整战略麻将 AI。

## HTTP 接口

请求和响应均为 JSON；静态资源由同一服务提供。

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/health` | 服务状态 |
| `POST /api/games` | 可选 `seed`、`policy`、`exchange`、`auto_pass`，返回牌桌观察 |
| `GET /api/games/{id}` | 真人 0 号视角，附设置、公开待应牌与结算 |
| `POST /api/games/{id}/action` | `{decision_id, action}`，返回最终 `view` 与动画 `frames` |
| `GET /api/games/{id}/replay` | 仅终局开放，下载完整可验证牌谱 |
| `POST /api/replays` | `{example:"three_winners"}`、`{game_id:终局ID}` 或 `{replay:完整牌谱}` |
| `GET /api/replays/{id}?step=N&reveal=false` | 查看指定命令步，可选离线全桌视角 |

游戏 ID 与回放 ID 是独立随机会话标识。内存最多保存 32 桌和 8 份回放，超出时淘汰最旧者。牌桌不是在线大厅，服务重启后内存牌局会丢失；需要保留时应下载终局牌谱。

请求上限 2 MiB，回放上限 2000 条命令。普通浏览器请求必须来自同一 Origin。静态路径限制在包内 `web` 目录。这是本地开发服务，未实现公网账号、房间匹配或持久化。

## 信息可见性与回放

普通牌桌与每个动画帧都从 `engine.observe(0)` 投影：隐藏未胡对手暗牌、未公开摸牌和其他玩家的密封选择。胡牌后按引擎规则亮牌；终局可查看全桌手牌。API 不返回完整牌山或完整事件私有字段。

离线回放先重放并验证完整状态和事件校验和，然后建立每 20 条命令一个的检查点。任意跳转至多重放 19 条命令，支持向前、向后及全桌视角切换。回放不提供可提交动作，导入或全桌视角不会改变真人牌局。

## 素材与验证

`scripts/generate_web_assets.py` 生成 34 种牌面、三种赤五、牌背、四个头像和标识，共 43 个原创 SVG。所有资源位于 `mahjong_sandbox/web/assets/`；无需引用第三方素材。生成命令：

```bash
python3 scripts/generate_web_assets.py
```

牌面采用常见中式排列，筒牌和条牌分别定义点位。二筒上下同绿，三筒两端蓝、中间红；六筒保留上方两点与下方四点的间距分组。筒圈按点数调整大小，竹节有明确的节环，便于小尺寸辨认。七筒上方三点斜列，三条呈三角，七条为上红一、下绿六，八条为上下相对的竹节，九条中列为红色；一条采用鸟形幺鸡。排列参考 [七筒图例](https://commons.wikimedia.org/wiki/File:MJt7-.svg)、[八条图例](https://commons.wikimedia.org/wiki/File:MJ8tiao.svg)与 [Unicode 麻将符号提案](https://unicode.org/wg2/docs/n3171.pdf)，由项目脚本重新绘制。`/tile-preview.html` 提供整套 37 种牌面预览。

`tests/test_web.py` 覆盖可见信息基线、真人与 AI 轮转、真人胡后继续、混合策略真实整局、所有动画帧的暗牌隐藏、重复命令拒绝、终局导出、回放前后跳转、坏牌谱拒绝、HTTP 路由、来源检查和资源路径边界。执行：

```bash
python3 -m unittest discover -s tests -v
```

本阶段验收时全量 58 项测试通过，其中新增 13 项服务、回放和基线测试；真实整局检查涵盖 12 局混合策略及配置。构建 wheel 后在独立目录验证了 37 个前端资源和内置牌谱，可脱离源码目录运行。

浏览器实测包括换牌、定缺、双击出牌、三位 AI 自摸至三家胡牌、账本结算、下载牌谱、JSON 文件导入、全桌视角、逐步回放、自动播放到终局和牌河放大；并检查桌面与手机布局和控制台。界面截图位于 `docs/screenshots/`。

## 阶段 4 增补

新局选择川麻或四人立直，日麻还可选择单局/东风/半庄、赤牌与食断。公开宝牌、场风、自风、本场、立直棒与本家振听状态均由引擎投影。选牌后可选择普通出牌或立直；吃牌候选显示完整顺子，赤牌消耗不同的候选分别保留。

单局终局后可复盘，整场终局后可下载整场牌谱；复盘支持局数跳转与结算。规则、新增 HTTP 路由、整场格式及验收说明见 [RIICHI.md](RIICHI.md)。上文 58 项及 37 个资源是阶段 3 当时的验收记录。
