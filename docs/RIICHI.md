# 阶段 4：四人立直麻将

`RiichiEngine` 实现版本化的 `riichi_4p_v1` 单局流程；`RiichiMatch` 管理东风与半庄。两者与川麻共享实体牌编号、动作 JSON、事件投影和回放协议，行牌及结算流程独立。运行无需第三方包。

## 打开牌桌与模拟

启动 `python3 -m mahjong_sandbox serve`，在“新开一局”选择“日麻 · 四人立直”。可选单局、东风战或半庄，以及赤宝牌和食断。真人固定坐 0 号，庄家会轮转；每局结束后点击“下一局”。

```bash
python3 -m mahjong_sandbox simulate --variant riichi --games 10 --policy greedy
python3 -m mahjong_sandbox simulate --variant riichi --match south --seed 21 --policy greedy --replay-dir replays
python3 -m mahjong_sandbox replay replays/round_21.json
python3 -m mahjong_sandbox replay examples/riichi.json
python3 scripts/validate_riichi.py --games 1000
```

`greedy` 使用本家观察中的牌效、可见牌及役牌副露计划，支持普通型、七对与国士的结构向听。它主动立直、保持赤牌并优先和牌，尚未训练；没有对手暗手或牌山输入。`random` 与 `win-first` 同样仅使用观察。批量并发、编译算子及 MaskablePPO 已接入；训练默认使用完整东风战，状态、赤牌动作、模型恢复及牌风评测见 [立直 RL](RIICHI-RL.md)。

## 默认规则配置

规则以配置和版本号为准，不声称与所有平台或赛事完全相同。番符和基础行牌参考 [WRC 官方规则资料](https://www.worldriichi.org/wrc-rules)；本项目有赤牌、途中流局与多家荣和等自己的明确配置，并非 WRC 2025 的复刻。

| 项目 | `riichi_4p_v1` 默认值 |
| --- | --- |
| 库存 | 136 张；34 牌种各四张，无花牌 |
| 起始点数 | 每家 25000；单局可传入分数、本场及供托 |
| 赤五 | 实体 ID `16 / 52 / 88`，万筒索各一张；基础牌种不变 |
| 和牌资格 | 至少一个役；宝牌、赤宝牌及里宝牌不能单独提供役 |
| 食断、食替 | 食断允许；禁止同牌及筋食替 |
| 吃碰杠 | 只吃上家；荣和优先于碰杠，碰杠优先于吃；同级按离舍牌者最近的次序 |
| 立直 | 门前听牌、至少 1000 点、活牌山至少 4 张；宣言牌未被荣和才扣棒 |
| 立直后 | 仅摸切或和牌；只允许包含本次摸牌且不改变等待及所有和型拆解的暗杠 |
| 振听 | 所有结构等待与自己的牌河相交即舍牌振听；过结构完成牌产生临时振听，到本家下一次摸牌解除；立直过和持续至本局结束。不能抢的普通暗杠不产生过和振听 |
| 振听与和牌 | 振听限制荣和；仍可自摸。无役等待也参与舍牌振听判断 |
| 一发与两立直 | 各家的第一次无鸣牌舍牌可两立直；立直成立后的下一次舍牌或任何鸣牌/杠提议取消一发 |
| 牌山、王牌 | 初始活牌山 122 张，王牌 14 张；发牌后 70 张活牌可摸，庄家先摸一张后剩余 69 |
| 杠与宝牌 | 最多四次岭上补牌；每次从活牌山尾部补充王牌。暗杠立即翻新指示牌，明杠与加杠在补牌后的舍牌翻开；连续杠会先翻上一张 |
| 抢杠 | 可抢加杠；暗杠仅国士可抢。被抢时不成立该杠、不补牌、不翻该张杠宝牌 |
| 里宝牌 | 仅立直和牌者计入；公开观察在有立直和牌的终局才显示 |
| 多家荣和 | 默认允许双响；三家荣和为途中流局，可单独关闭；可配置头跳 |
| 途中流局 | 九种九牌、四风连打、四家立直、四杠散了、三家和了；均连庄。四杠由同一人完成不散了，其他情况允许第四次岭上和牌及舍牌荣和后再流局 |
| 荒牌流局 | 自动判断结构听牌，听牌罚符总额 3000；两听两不听各家得失 1500，无人/全员听牌不支付 |
| 流局满贯 | 舍牌全部为幺九字牌且未被鸣走、没有明副露；按满贯自摸支付，不再支付听牌罚符。本配置按流局处理连庄，供托保留 |
| 点数 | 逐笔进位至百点；不开切上满贯，允许累计役满、役满复合及双倍特殊等待役满 |
| 本场、立直棒 | 荣和每个本场多付 300，自摸每家多付 100；多家荣和各得本场，最近的和牌者取得供托 |
| 包牌 | 支持大三元、大四喜及第四次大明杠完成四杠子的责任支付；复合役满只包相应部分 |

Python `RiichiConfig` 可配置上述开关；完整配置进入牌谱。副露后的结构张数仍按每个面子三张计数，四张杠牌全部参与宝牌与库存计数。

## 和型、役和符

支持普通四面子一雀头、七个不同牌种的七对子、国士无双。川麻的四张当两对规则不用于日麻。计分遍历所有和型和和牌位置，选择最高支付结果；荣和完成的刻子按明刻计算符及暗刻数。

一般役包括立直、两立直、一发、门前清自摸、断幺九、平和、一杯口、二杯口、役牌、一气通贯、三色同顺、三色同刻、对对和、三暗刻、三杠子、小三元、七对子、混老头、混全带幺九、纯全带幺九、混一色、清一色、岭上开花、抢杠、海底摸月及河底捞鱼。按门前/副露分别计番，宝牌再附加。

役满包括国士无双、四暗刻、大三元、小四喜、大四喜、字一色、绿一色、清老头、九莲宝灯、四杠子、天和及地和。开启双倍时，国士十三面、四暗刻单骑、纯正九莲及大四喜为双倍。地方役（如大车轮、人和、八连庄）不在此规则版本中。

符考虑门前荣和、自摸、役牌雀头、单骑/嵌张/边张、明暗刻及明暗杠、幺九字牌。平和自摸 20 符，平和荣和 30 符，七对子固定 25 符；其他进位到十符，无符副露和牌至少 30 符。连风雀头按 4 符。满贯及以上按限额支付。

## 对局循环

`MatchConfig` 使用 `riichi_match_v1`，默认半庄、30000 点目标、负分飞人、南四庄家第一且达目标和牌止、不开听牌止；可选东风战。和牌连庄及庄家听牌连庄；流局增加本场，非庄和牌换庄时本场归零。分数与未领取立直棒传递到下一局。

最后一局换庄时若无人达目标，默认延长一圈（东风入南、半庄入西）；延长中有人达目标即结束，否则延长第四局换庄后结束。延长圈仍可连庄。平分按初始庄家起始的座位次序排列；终场剩余供托一次性给第一名，保存在 `final_scores` 中，原单局账本保持可复现。此版本暂不计算顺位马点与返还点。

```python
from mahjong_sandbox import RiichiMatch, MatchConfig, RiichiAgent, Phase, save_replay

match = RiichiMatch(MatchConfig(length="east"), seed=21)
agents = [RiichiAgent(seed=p) for p in range(4)]
while True:
    engine = match.engine
    while engine.state.phase != Phase.TERMINAL:
        player = engine.next_player()
        obs = engine.observe(player)
        engine.submit(player, agents[player].act(obs), obs["decision_id"])
    match.complete_hand()
    if match.ended:
        break
    match.next_hand()
print(match.final_scores, match.summary()["ranking"])
save_replay(match, "replays/east.json")
```

## 接口与可见性

单局接口仍为 `observe(player) / legal_actions(player) / submit(player, action, decision_id)`。新增动作 `chi` 消耗本家两张牌、`riichi` 指定宣言舍牌、`abort_nine` 无参数。使用相同结构化候选 JSON，副露保留具体赤牌身份。

日麻观察增加场风、自风、庄家、局数、本场、供托、公开宝牌指示牌、赤牌配置；公开各家立直状态与宣言舍牌索引，仅本家看到振听与一发状态。暗牌、密封响应、里指示牌和未来牌山均不会进入普通观察。终局前禁止完整牌谱导出。

比分账本中 `payer / receiver = 4` 表示供托账户，非第五位玩家。单局保持：

```text
sum(scores) + riichi_sticks * 1000
    == sum(initial_scores) + initial_riichi_sticks * 1000
```

每次接受命令检查全部 136 实体的唯一库存、王牌与岭上计数、副露、手牌张数、响应与账本。完整 `State` 和完整牌谱是裁判信息，不应传给训练策略。

## 回放与验收

单局沿用格式 v1，通过 `config.rule_version` 选择对应引擎；日麻 `exchange_offset` 为 `null`。旧川麻示例的状态与事件校验和保持兼容。整场格式 v2 保存完整初始配置、每局固定牌墙与命令及终场结果；验证每局校验和以及换庄、连庄、分数和供托传递。固定牌墙重放不依赖随机洗牌实现。

牌桌可导入两种 JSON。整场复盘增加局数选择，每个下一局开局也是独立的一步；保持任意前后跳转、检查点与离线全桌视角。每局结束可下载单局牌谱，整场结束可下载整场牌谱。HTTP 新增 `POST /api/games/{id}/next`，请求包含当前 `decision_id` 与 `hands_played`；`GET /api/games/{id}/replay?match=true` 只开放已结束整场。

`tests/test_riichi.py` 覆盖确定番符点数、特殊和型与役满、立直扣棒/一发、所有振听、吃碰优先及食替、三种杠、抢杠、立直暗杠限制、途中流局、流局满贯、听牌罚符、包牌及对局终止；`tests/test_riichi_web.py` 覆盖实际整局、动画帧隐私、设置、整场推进与 JSON 回放。`scripts/validate_riichi.py` 混合四组规则与三种策略，串行跑真实洗牌整局，每条命令检查库存和点数，抽样重放；报告见 `riichi-validation.json`。

37 种牌面（34 牌种加三种赤五）及牌背、头像均为原创 SVG。预览在 `/tile-preview.html`；桌面及移动端验证截图保存在 `screenshots/`。

本阶段最终验收：全量 103 项测试通过。1000 局混合验证产生 232 局荣和、75 局自摸、683 局荒牌流局、9 局四家立直及 1 局四风连打，共 309 名和牌者；20 份抽样牌谱重放通过，每条命令均检查库存与点数。该验证耗时约 659 秒，属于串行正确性检查。浏览器实测完成立直、摸切锁定、2 番 40 符荣和、一本场连庄，以及 JSON 整场导入、局数跳转和结算；移动端无页面横向溢出、牌面加载错误或控制台异常。wheel 在独立目录加载并检查了 49 个资源、两份示例及真实日麻整局。
