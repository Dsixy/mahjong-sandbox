# 川麻自博弈：CPU / H200 运行时间对照

2026-10-19 的短时实测支持当前基线使用 CPU 训练。H200 明显加速 PPO 更新，但整轮吞吐仅提升约 13%；下一步应优化采样流水线，再考虑扩大 actor 数量。

## 测量条件与结果

在正式任务已分配的同一节点内顺序运行 CPU、CUDA 诊断，不额外申请 GPU。节点 CPU 为 Xeon Platinum 8558，正式任务资源为 16 CPU、1 H200、64,000 MiB；正式学习者继续运行，与诊断共享该份资源。这不是独占节点基准，不能把短时差值当作所有 CPU 机型上的精确加速比。

两边均用相同的固定镜像、PyTorch 2.8.0+cu128、307,200 步检查点、冻结的历史对手池、规则、种子和 PPO 超参。128 局、8 个 worker、64 步 rollout，每次更新 8,192 次学习者决策，minibatch 1,024，4 个 epoch，Torch 线程数为 1。每种设备做 3 次更新，排除首轮后汇总后两轮；不计启动/JIT、验证、检查点与快照发布。CPU/CUDA 的随机采样轨迹不保证逐位相同。

| 每轮平均耗时 / 吞吐 | CPU | H200 |
| --- | ---: | ---: |
| 采样 | 39.30 秒 | 38.97 秒 |
| 其中：主进程特征编码 | 19.38 秒 | 19.78 秒 |
| 其中：环境等待、规则推进和重置等 | 19.19 秒 | 18.86 秒 |
| PPO 更新 | 5.26 秒 | 0.33 秒 |
| 采样 + 更新 | 44.56 秒 | 39.30 秒 |
| 学习者决策 / 秒 | 183.84 | 208.43 |

表中的“其中”已经包含在采样耗时内，不能再次相加。环境分段包含等待 worker 的时间，不是 worker 内部 CPU 时间的求和。完整逐轮数据、哈希、版本及任务状态见 [原始报告](longrun-runtime-profile.json)。

PPO 更新本身加速约 16 倍，但 CUDA 下采样占整轮约 99.15%。模型只有 231,234 个参数；正式任务显存约 1,505 MiB。诊断前约 14 秒的短窗口中，GPU 利用率采样为 0～1%，主进程约使用 0.50 个核，8 个 actor worker 合计约 1.87 个核。这个窗口可能漏掉短暂更新峰值，不能代表全程平均 GPU 利用率。

## 资源与扩展选择

当前可以使用 CPU 学习者和 CPU worker，保留 CUDA 接口及跨设备恢复能力。H200 提供约 13% 的整轮吞吐提升；如果优先考虑当前硬件利用效率，CPU 是合理选择。当前没有测出最优 CPU 线程数或 worker 数，不能据此声称增加 worker 一定提速。[SB3 的 PPO 文档](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)也建议非 CNN 策略尝试 CPU 和多进程环境；具体选择仍应以本项目实测为准。

优先优化主进程串行的特征/牌效计算，将学习者特征生成下放到环境分片；然后把历史对手的逐动作单条推理改为批量推理。当前是“整批动作 → 等全部分片完成 → 主进程编码 → 下一批动作”的同步循环，扩 CPU 核心或只把 128 局改成 1,024 局，都不会自动消除这些串行成本。

采样率提高之后，再比较 CPU 学习者与集中 GPU 学习者。扩大 `n_envs` 时要同时管理 `n_steps`、rollout 总量、minibatch 和更新频率，并以独立评测净得分检查学习效果；提高资源利用率本身不是策略质量指标。异步采样还需要限制 PPO 策略版本滞后。

本次仅完成诊断，未迁移正式训练，也未更改训练目标。最初排队的零 GPU CPU 诊断任务已停止；同机诊断已退出并释放额外进程/GPU 上下文，正式任务继续运行。

## 复跑

在安装本项目 RL 依赖的环境中，从仓库根目录执行；对手清单应先复制到独立目录，引用已保存的不可变快照。报告路径必须尚不存在。每种设备使用相同输入并分别启动，长时对照优先使用空闲节点。

```bash
PYTHONPATH=. python scripts/profile_policy_runtime.py \
  --config configs/rl/policy-longrun.json \
  --checkpoint /outputs/checkpoints/step_307200.zip \
  --manifest /profile/opponents.json \
  --output /profile/cpu-report.json \
  --device cpu --workers 8 --updates 3
```

改用 `--device cuda` 与新的报告路径可测 GPU；`--workers 4 8 16` 可顺序测多个分片数。脚本不发布模型、快照或训练检查点，记录采样、编码、网络前向和更新耗时；CUDA 使用同步边界计时，参照 [PyTorch 2.8 CUDA 计时说明](https://docs.pytorch.org/docs/2.8/notes/cuda.html#asynchronous-execution)。小规模 CPU 验收已完成 2 次更新、8 次决策，并核对计时分段和正数吞吐。
